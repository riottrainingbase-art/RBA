## 3. 顧客が寝ている時間に進められる範囲

1. 公開アプリ／サイトで商品を探す。
2. 既存公式サイト・note・Stripe等へ進み、条件に同意して自発的に申込・支払を行う。
3. 決済事業者が会計・領収書・月額更新を扱う。ウェブサイトでカード番号を預からない。
4. HOME COURTの契約照合には既存のSupabase `stripe-homecourt-webhook` が稼働中。Stripe署名検証、重複イベント除外、契約状態の更新を行う実装がある。
5. 商品によっては参加資格・会員アクセス・広告掲載など追加の手動確認が必要。購入画面が表示されたことだけでは納品完了ではない。

## 4. 夜間の運用タスク

既存のChatGPTオートメーション「RBA夜間売上オペレーション」(`6b0184e5e9a48191b74d3920c9a16821`) は毎日02:00 JSTに1回実行するよう設定済み。毎回次の差分を整理する。

- 新規決済・返金・決済失敗・月額契約／解約（RBA Stripe本番だけ。JPNentry等の別事業アカウントと混同しない）。
- Square・noteの直接取引明細を取得できない場合は「未確認」に置き、推測の売上を足さない。
- 新規申込の放置、支払済みなのに会員画面へ入れない人、広告掲載の納期遅延を優先抽出する。
- 明確な同意のある成人の問い合わせだけに、相手が求める内容に沿った自然な日本語／英語の返信下書きを用意する。自動送信しない。
- 未成年者や配信停止希望者への勧誘、支払済みの方への再請求、一括無差別営業をしない。
- 前日比が追跡できない指標は勝手に補完しない。

## 6. 最低限の売上・品質KPI

毎日の朝レポートは、集計可能な場合のみ以下を分ける。

1. **確定売上：** 成功決済・通貨・返金・手数料（プロバイダーごと）。
2. **月額売上の基礎：** active/trialing件数、実際の単価、解約予定、決済失敗（note/Squareは別）。
3. **導線：** アプリ訪問、ボタンクリック、申込フォーム完了、決済完了。計測できない項目は「不明」。
4. **購入後の対応：** 未提供・閲覧不可・返金待ち・広告掲載素材未提出。
5. **安全指標：** 二重請求0件、同意なし営業0件、視聴許可なし録画配布0件を維持。
