# D-HUB PROJECTS operating guide

## Purpose

D-HUB PROJECTS connects real RBA work with suitable D-HUB COACH LAB members.

It is not:
- a promise of employment,
- a paid job board,
- a certification marketplace,
- a system where higher-paying members receive priority,
- or a reason to create artificial projects.

The value of D-HUB membership remains coach development. Projects are an additional pathway from learning into real practice.

## Demand intake

External teams, clubs, schools, organisers and partners submit a request through:

https://form.jotform.com/262722347194056

Before a request becomes a D-HUB project, RBA confirms:
1. Who is requesting the work.
2. Development purpose.
3. Target age group.
4. Location and date.
5. Participant count.
6. Required role(s).
7. Budget and compensation.
8. Travel / accommodation treatment.
9. Required experience, credentials or language.
10. Safeguarding responsibilities.
11. Cancellation conditions.
12. Who holds final operational responsibility.

A form submission is not a confirmed booking.

## Project lifecycle

DRAFT → OPEN → MATCHING → FILLED → COMPLETED

Alternative terminal state: CANCELLED

Use DRAFT until the project is sufficiently defined to show members. Use OPEN only after the role, location, timing, compensation/expenses and basic safety requirements are clear enough to make a responsible application decision.

## Member application lifecycle

SUBMITTED → REVIEWING → SHORTLISTED → SELECTED → COMPLETED

Alternative states: NOT_SELECTED / WITHDRAWN

Selection must be based on project-relevant requirements such as relevant age-group experience, coaching or operational experience, required verified credentials, language, location/travel practicality, availability, safeguarding suitability, and the actual role.

Do not rank applicants by popularity, social following, D-HUB tenure or willingness to pay.

## Compensation rules

Default to paid work when RBA is selling a paid client service. If a role is expenses-only or volunteer, state that before application and explain why that structure is appropriate.

Never use experience as a substitute for disclosed compensation.

Before assignment, confirm gross fee or agreed rate, travel reimbursement, accommodation, meals if relevant, expected hours, preparation/follow-up work, cancellation, invoicing and payment timing.

D-HUB does not charge members an additional fee to apply for work.

## Safeguarding

Any project involving minors requires role clarity and safeguarding review. Depending on the assignment, confirm identity, relevant credentials, supervision responsibility, photography/video handling, emergency contact process, transport responsibility, overnight-stay responsibility, medical/injury escalation and communication boundaries.

A D-HUB profile is not proof that a credential is valid. Verify credentials when a project requires them.

## Project profile privacy

D-HUB project profiles are private matching data. They are not a public directory. Only collect information needed for project matching.

## Communication

Primary project board: /ja/d-hub/coaches/member/projects

D-HUB community: BAND

Client project intake: https://form.jotform.com/262722347194056

Use the project board as the source of truth for structured project conditions. BAND can announce a project and support discussion, but should not replace the formal project terms.

## Notifications

When a member-visible project opens, D-HUB creates an announcement. When an application status changes, the applicant receives a platform notification for reviewing, shortlisted, selected, not selected, withdrawn or completed.

Notifications never imply guaranteed payment or assignment beyond the stated project status.

## Revenue principle

Preferred flow:

Client → pays RBA for a real service/project → RBA scopes, sells, contracts, coordinates and quality-controls the work → suitable member(s) deliver agreed roles → member receives agreed compensation → RBA retains the portion justified by sales, design, coordination, administration, safeguarding and quality responsibility.

The project network should create value because real work exists, not because access to opportunities is being sold.

## Metrics to monitor

Track client requests received, requests converted into real projects, open projects, applications, fill rate, time to fill, projects completed, member compensation paid, RBA project gross margin, repeat clients, member repeat assignments, cancellations, safeguarding/operational incidents and post-project feedback.

Do not use number of job listings as the primary success metric.
