# RBA佐賀｜かんたん更新ガイド

RBA佐賀ページは、基本的に **`content/saga.json` だけを編集すれば更新できる** 形にしています。

ページ本体のTSXを毎回触る必要はありません。

## まず更新する場所

`content/saga.json`

主に触るのは次の5か所です。

### 1. 更新日

```json
"updatedAt": "2026-10-04"
```

ページ内の更新表示とサイトマップの更新日に使われます。

### 2. 次回開催

```json
"nextEvent": {
  "status": "planned",
  "titleLine1": "次は、年末に佐賀で。",
  "titleLine2": "12月28日・29日を予定しています。",
  "body": "...",
  "notice": "...",
  "dates": [...],
  "registrationUrl": null
}
```

#### まだ先行案内だけの場合

`status` は `planned`、`registrationUrl` は `null` のままにします。

この場合、ページにはLINE案内ボタンが表示されます。

#### 申込を開始した場合

申込URLが決まったら、

```json
"status": "open",
"registrationUrl": "https://..."
```

に変更します。

ページ側は自動で **「申込・詳細を見る」** ボタンへ切り替わります。

### 3. 過去開催を追加

`history` の先頭または末尾に1件追加します。

```json
{
  "date": "2027 / JAN",
  "title": "佐賀・NEW YEAR CLINIC",
  "body": "開催内容を自然な日本語で短く。",
  "applications": 30
}
```

`applications` を入れると、ページ上部の申込記録合計も自動で更新されます。

実参加人数ではなく申込記録しか確認できない場合は、必ず申込記録の数字を入れます。

### 4. FAQ

質問が増えたら `faq` に追加するだけです。

### 5. 今後やりたいこと

`roadmap.items` を編集します。

確定していない内容は「開催決定」のように書かず、方向性として自然に表現します。

## 日本語のトーン

RBA佐賀は、事業計画書のような言い回しより、選手・保護者が読んで自然な言葉を優先します。

### 使いたい言葉

- 今のチームを大切にしながら
- もう一つの学びへ
- また佐賀で
- 練習したことをゲームの中で
- 見て、考えて、選ぶ
- 一度きりで終わらない
- 詳細は決まり次第お知らせします

### できるだけ避ける言葉

- 参加価値
- 外部環境
- 事業運用
- 実装
- 転移
- 申込選手枠
- 地域ハブ
- 未算入
- データ構造

必要な注意書きは残しつつ、本文はできるだけ普通の日本語で書きます。

## 更新時のチェック

1. `updatedAt` を更新
2. 日付・曜日・時間を確認
3. 「予定」と「募集中」を混同していないか確認
4. 申込記録と実参加人数を混同していないか確認
5. 申込開始時だけ `registrationUrl` を入れる
6. スマホ表示を確認
7. QA通過後に公開

## 画像

開催写真や告知画像を増やす場合は、本文データとは分けて管理します。

頻繁に差し替える画像を今後追加する場合も、同じ `content/saga.json` から参照できる形に拡張できます。
