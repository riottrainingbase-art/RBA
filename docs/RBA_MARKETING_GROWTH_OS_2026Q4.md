# RBA Marketing Growth OS — 2026 Q4

## Objective

Turn RBA's existing activity into a measurable acquisition and retention system without increasing Masato Nishio's field workload.

The operating idea is simple:

**Issue / insight → trust → RBA ID / LINE → paid opportunity → repeat participation / membership → referral / partner**

RBA should not market itself as a list of programmes. It should market one clear promise:

> 今いるチームを大切にしながら、地域の外にも学びと挑戦を。
> RBAは、全国・アジアの育成機会につながるプラットフォーム。

## Current diagnosis

### Strong assets
- Real activity across Japan plus Asia-facing partnerships.
- Clear player-centred development philosophy.
- High-volume editorial output through note / social content.
- Existing RBA ID / MY HOME COURT infrastructure.
- Existing LINE audience and owned website.
- Multiple paid offers already built in Stripe.

### Bottlenecks
- Too many public offers create choice overload.
- Public activity, editorial content and checkout are not one funnel.
- Measurement is incomplete: Search Console and Metricool are not yet connected.
- Old public links still point to legacy destinations.
- Public numbers and proof points are not presented with one consistent definition.
- Checkout inventory is much larger than current proven demand.
- Event lifecycle needs strict automation so finished events disappear automatically.

## Content mix

Do not stop provocative content; rebalance it.

- 40% problem / structural issue
- 25% field evidence and participant outcomes
- 15% practical coaching / S&C education
- 10% Japan × Asia proof
- 10% direct offer

Every post must have one next action only.

### Problem-led content is an acquisition engine

Problem-led content remains RBA's largest organic reach lever. Do not reduce it simply to look more corporate. Instead, give every provocative post a second layer:

1. State the question clearly.
2. Show what is known from evidence or official guidance.
3. Explain the structural reason the problem persists.
4. Offer a practical alternative.
5. Show what RBA actually does.
6. Send the reader to one next step.

The goal is not outrage. The goal is **recognition → reflection → trust → action**.

Use three families of questions:
- **Child-centred contradiction** — "Is this really for the child?"
- **Evidence vs tradition** — "Is the common practice actually supported?"
- **System / structure** — "What in the rules, culture or incentives creates this?"

Examples:
- Issue post → full article / RBA ID.
- Clinic proof → next opportunity.
- Coach insight → D-HUB / Torsten.
- International proof → partnership enquiry.
- Sponsor story → partner page.

## One-activity content engine

Every clinic / camp / exchange should produce:
1. 1 field note.
2. 1 vertical video.
3. 1 carousel.
4. 3 short Threads posts.
5. 1 LINE recap / next-opportunity message.
6. 1 participant follow-up email.
7. 1 reusable proof block for sponsor / host pages.

Do not create seven original pieces. One source observation is repurposed seven times.

## Conversion rules

- No page should present more than 3 primary CTAs.
- Finished events must automatically leave all "open" lists.
- No legacy Wix links in owned profiles.
- All campaign links use UTM naming:
  - source: instagram / threads / line / note / partner
  - medium: organic / broadcast / referral / email
  - campaign: offer_slug_YYYYMM
- Store source / campaign through application and payment where technically possible.
- Every paid participant receives the next recommended action within 24 hours.
- Every inactive lead receives one useful follow-up, not repeated sales pressure.

## 30-day execution

### Week 1 — Clean
- Remove expired programmes everywhere.
- Standardise proof-point definitions (e.g. all-time participants vs since-mid-2025 participants).
- Replace legacy public links.
- Archive or deactivate obsolete Stripe products / Payment Links after verifying they are no longer in use.
- Connect Search Console and Metricool.

### Week 2 — Funnel
- Add UTM conventions.
- Make RBA ID / LINE the default owned-audience capture.
- Create participation follow-up template.
- Give each active offer one landing page, one application path and one payment path.

### Week 3 — Proof
- Publish one Japan field case.
- Publish one parent / participant proof case with consent.
- Publish one coach-learning case.
- Publish one Japan × Asia partnership proof case.

### Week 4 — Scale
- Build HOST RBA package.
- Build sponsor / partner proof deck.
- Create repeat-host and referral sequence.
- Review funnel metrics and cut any offer with activity but no strategic role.

## Non-negotiables

- No child ranking or exploitative urgency.
- No unsupported performance claims.
- No product creation without a defined audience, CTA and measurement plan.
- No event stays "open" after its end date.
- No new channel until existing channels are measurable.
- RBA should scale through systems, partners and reusable IP—not Masato Nishio doing more hours on court.
