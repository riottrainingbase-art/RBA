# RBA STORE｜RBA管理型・販売／入金／製造委託運用手順
2026-11-21 改訂／社内向け。**ユーザーから確認した責任分担**を反映。既存PR #519の販売停止ゲートを維持。

## 役割分担（最終運用方針）
| 工程 | 実務責任 | 記録の正本 |
| --- | --- | --- |
| 商品、販売価格、最終表示 | RBA | RBA公式サイト・承認済み商品仕様 |
| 購入者の支払い／入金照合 | RBA | RBA名義Stripe liveアカウント |
| 受注、キャンセル、返金承認、購入者対応 | RBA | 署名検証済Stripe event→`rba_essentials_orders`、決済証跡 |
| 工場／りささんへの製造依頼 | RBA（委託先との連絡責任） | RBA専用非公開製造タスク、委託先の受理記録 |
| ボディ調達、印刷／縫製、検品、梱包、発送 | りささん／正式に合意した製造先 | 委託先の製造・検品・発送記録 |
| 配送追跡の入力、購入者への発送通知 | RBA | RBA管理画面・Stripe検証・通知ログ |

りささんのSupabase / RBA HOMECOURTアカウントは、**RBA管理方式では不要**です。
外部担当者にアカウントを作る場合の画面は任意・別承認。RBAのStripe・売上情報・返金権限は製造先に渡しません。

## 設定とシステムの安全ゲート
- `RBA_ESSENTIALS_FULFILLMENT_MODE=rba_managed` でRBA管理方式を選択。
- `RBA_ESSENTIALS_RBA_OPERATOR_USER_ID` はRBA管理者の**既存・メール認証済み**SupabaseユーザーID。管理者権限も実データで検証する。IDを推測しない。
- `RBA_ESSENTIALS_RBA_OPERATOR_ACCOUNT_VERIFIED=true` は実際の本人確認と管理権限を監査後に承認する。自己申告だけで変更しない。
- `RBA_ESSENTIALS_RBA_SUPPLIER_HANDOFF_VERIFIED=true` は**実際に製造依頼を出し、委託先が商品・仕様・数量・加工・納期を確認し受理したテスト**の記録があるときのみ承認する。
- それとは別に既存の製造契約・実物サンプル・サイズ表・特商法表示・発送期限・返品条件・Stripe署名Webhook／購入者通知・税・価格の各ゲートを満たす必要がある。
- `RBA_ESSENTIALS_PREORDER_ENABLED` の `false` はこの運営方式の変更では解除しない。決済リンクも未承認のまま有効化しない。

## RBA担当者の操作（有料販売がすべて正式承認されてから）
1. 公式サイトで商品・数量・サイズ・税込総額・送料・返品条件・引渡期限を提示する。
2. 受注／入金をRBA名義Stripeが処理。**Stripe入金成功と署名済イベントを確認した注文だけ**RBAの注文台帳に記録する。二重イベントは一注文に統合。
3. RBA管理者のみ `/ja/essentials/manage` で入金済注文を照合し、`/ja/essentials/production` で製造タスクを確認。
4. 委託先へ安全な方法で製造指図を伝える：注文識別子、商品SKU、サイズ、数量、加工内容、発送期限。購入者のメール・電話・決済明細は渡さない。
5. 発送に必要な宛先のみ、契約・適法な本人同意／告知の範囲で適切な経路にて提供する。公開URLやGitHub、一般チャット、Supabaseの製造タスクには住所・連絡先を保存しない。
6. 委託先の実受理を確認したRBA管理者が `accepted_by_production`、素材確認後 `materials_ready`、製造中 `making`、検品中 `quality_check`、梱包後 `packed`、**実際の運送会社・追跡番号・発送日を取得した後だけ** `shipped`、配達記録後 `delivered` へ遷移する。未対応や事故時は `problem` に記録する。
7. 受注承諾・発送通知は認証済みRBA差出元と二重送信防止を検証した後に送信し、配送完了を送信APIの受理と混同しない。
8. 返金・取消はRBAのみに許可し、元取引ID・規約・実際の証拠に従って実施する。製造担当へStripe権限を渡さない。

## 起動前の実証テスト
- RBA管理者がログインして注文と製作タスクにアクセスでき、外部未認証者は不可。
- Stripe以外の通知／無効署名／異なるStripeアカウントを拒否。
- 既払イベントの重複で注文・製造タスク・購入者通知が増えない。
- 実際のサイズ（TEE S〜XL、HOODIE S〜XXL、PANTS M〜XL）以外がサーバーとWebhook両方で拒否される。
- 受注→RBA製造依頼→委託先受理→発送ステータス→通知のテストが完了し、RBAと委託先で原本証跡を保管。
- 注文不可状態での決済アクセスは423、未ログインの管理画面アクセスは404。
- 発売前は契約済み、サンプル検品済み、製造完了、発送済み等の事実がない限り表示しない。

**状態:** 運用方式とコードを整備中。製造委託先のログインは不要だが、契約・発送能力・本人確認・署名Webhook・注文通知等の未検証事項が自動で解消されるものではない。本番の有料注文は別途正式ゲート通過後に開始する。
