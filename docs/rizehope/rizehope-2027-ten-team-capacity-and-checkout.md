## 3. 先着順位の基準と不正・重複を防ぐ運用
- 同一チームの複数回答、表記揺れ、代表者アドレス違い、複数フォーム登録をチェックする。チーム名+代表者+連絡先+所属地域を照合。
- 既存の無料意向登録には競争枠を確約しない。全窓口の応募日時を照合し、条件変更を既存登録者へ不利に遡及させないよう、先着順位の確定前に運営側で判断する。
- 公平性のため、公開可能な「先着10チーム枠」の順位は国内の正式申込希望フォームの送信日時を基本にし、従来の関心表明と混同しない。海外チームも出場確定した場合には総10チームに含む。
- **このJotformコネクターでは送信10件での厳密な自動ロック、複数フォーム横断の原子的な10枠制御を検証できない。** 先着順はあくまで優先審査順。公開の「残り○枠」は実際の支払/承認数と照合が完了するまで表示しない。
- 定員は当日の試合時間、2コート使用可否、カテゴリー、審判/TO、救護、待機/休息を満たす範囲で最大10チーム。10の数を無条件の出場保証としない。
- 状態は '申込希望' → '重複/資格照合' → '承認待ち' → '正式受諾' → '決済案内' → '入金確認済' → '確定'。キャンセル待ちは別ステータス。
- 入金確認はStripe管理画面/APIの確定支払（succeeded / paid）で行い、フォームの送信だけで有料参加確定としない。
- 支払期限は主催者と書面合意するまでは設定しない。失効・補欠繰上げ・返金処理は手動確認を要する。

## 4. 66,000円のStripe決済を解禁するまでの必須条件
- 正式主催・集金主体の名義、参加規約、試合カテゴリー、出場資格を確定し、未成年選手の安全・救護/保護者同意・競技可能条件を定める。
- キャンセル・返金条件を料金支払前に個別確認できるURLとして公開し、参加者が同意できるようにする。主催者都合で開催中止した場合の返金原則、自己都合の取扱い、決済手数料、移動宿泊の扱い等を明示。
- 税込総額66,000円の税務区分を確認。RBA Stripe account: `acct_1UGdxZRXDnnSs6XN`。2026-11-19時点のStripe Tax settings status=activeだが登録 jurisdiction=0。Stripe Taxは登録地が無ければその地域の税を自動で徴収しない。登録先を推測して設定しない。
- 商品税区分はStripe Taxの検索候補（スポーツ競技参加費 `txcd_50012003` 等）を税務責任者/ユーザーが確認後に設定する。一般サービスコードのまま黙って公開しない。

- 支払を受け付ける場合には、チームの受付番号→Stripe Checkout/payment_link ID→PaymentIntent ID→paid statusの照合を最低要件とする。二重決済があれば自動返金・二重請求を勝手に行わず、担当者が確認。
