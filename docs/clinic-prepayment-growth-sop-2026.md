# RBA CLINIC / CAMP｜申込・前払い・入金後案内 共通運用ルール（2026/11版）

目的：選手・保護者が迷わず申込から支払いまで完了でき、主催者が**実際の入金**で参加枠を管理できるようにする。売上拡大と保護者の安心を両立するための標準手順。

> 適用条件：イベントの日程・場所・提供内容・税込料金・定員・安全体制・キャンセル規定が確定していること。未承認・会場未確定の販売を開かない。自動請求はせず、申込者の明示的な決済操作で受領する。既存購入者に新プランを再販売しない。

## 1. 受付導線の基本原則

- **単発クリニック・オンライン講習：原則全額事前決済。** 見積りの少額化・現地集金・銀行振込を複数案内するほど未入金や照合工数が増えるため、公開済み正規の申込ページを第一案内とする。カード以外の決済手段は個別相談で対応し、決済済み・銀行振込済みを必ず照合する。
- **合宿・高額チーム参加：全額事前決済、または個別承認された前金＋残額。** 50%を前金として採用する場合は、税込総額・前金額・残額・残額支払期日・対象となる返金条件をお申込前に書面で提示。前金の振込を受けただけでは、運営が確認していない宿泊枠・引率・航空券を確約しない。
- **無料相談と有料申込は別ステータス**。フォーム送信＝申し込み確定ではない。決済成功通知と保護者同意、年齢・参加形態・残席を照合して受付を確定する。
- **既存参加者の優先保護**。同一選手／同一家族／同一イベントについて、Stripe / Square / 銀行振込 / 代理支払 / 共同主催者受付とキャンセルを照合。メールアドレスが同じでも兄弟姉妹2名分なら適法な2決済のことがある。金額だけで二重決済と判定しない。
- RBAは実在する定員・申込締切しか公表しない。「残りわずか」「本日限定」は根拠がある時だけ。返金されない前金を一律設定しない。
- 決済メールにカード番号・セキュリティコード・健康の詳細を要求しない。参加者の個人情報・決済ID・秘密鍵を公開GitHub・SNSに記載しない。

## 2. 申込ページで必要な情報

1. 何が学べるか：対象年齢、当日のテーマ、指導者、練習の内容と成果のイメージ
2. **確定済みの日付と時刻、会場、費用、含まれる／含まれないサービス**。条件が未確定なら未確定と書く
3. 税込総額と参加プランの違い。保護者1名が選手ごとに同意・入力して申し込める
4. 最も目立つCTA「参加日・プランを選んで申し込む」→正規のフォーム/Checkoutへ
5. CTA直下に「送信のみでは未入金、入金照合後に受付案内」「既入金者は再決済不要」
6. キャンセル期限・返金の計算・主催者都合中止時の対応・問い合わせ先へのリンク
7. 未成年の場合、保護者による同意、緊急連絡先、スタッフ受付・引渡し・保険の必要事項
8. ボタンを押しても決済が開かない場合の問い合わせ先。重複クリック時に二重請求しないよう注意書き

## 4. Stripe・他決済手段の照合ロジック

- 親メール／参加者名／イベントID／プラン／受講日を照合する。個人情報の保存はアクセス制限付き台帳のみ。
- Checkout Session `payment_status=paid`、当該PaymentIntent `succeeded`、返金・争議の状態を確認。支払い済みと最終参加確定は分ける。
- Square・銀行振込・共同主催者経由がある場合は、Stripeの未入金判定だけで催促しない。
- 支払成功後：保護者に「入金確認／追加決済不要／参加日時と会場／持ち物／必要な返答事項／キャンセルの連絡先」を案内する。
- 入金未確認・申込済みの方にだけ：支払い方法と案内URLを**1回**案内し、未払い・未確定であることをやわらかく説明。無回答なら明示された期日に合理的な1回の再案内。申込を辞退した方、返金処理中の方、過去に送信停止を求めた方には送らない。
- 機械的な大量催促よりも、「初回案内→対象者の個別照合→1回の必要なフォロー」にする。マーケティングの案内は情報受信に同意した方だけ。

## 6. 運営者向け販売指標（個人を特定しない集計）

毎週イベント別に以下を集計して、必要な部分だけ改善する：

- イベントページ閲覧数、申込CTAクリック数、申込フォーム送信数
- チェックアウト開始数、入金成功件数、重複・返金・未入金件数
- 参加者人数（ユニーク選手数）、リピート率、当日の無断欠席数
- 参加後のフィードバック回収率、リピートクリニック紹介希望
- 有料参加の目標と収支：売上だけでなく会場費・指導料・移動費・決済手数料・保険等の粗利を確認

目安として「チェックアウトまで到達しても未決済が多い」なら導線・金額の誤認やフォーム入力を先に改善。「申込ボタンが押されない」なら対象・価値・時間・会場の明確化を優先する。
